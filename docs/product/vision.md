Vision produit — LUKA TRIBUNAL
1. Identification
Nom du produit : LUKA TRIBUNAL
Pays : République Démocratique du Congo
Version documentaire : 1.0
Statut : Document de référence
Phase actuelle : Conception et MVP expérimental
2. Présentation
LUKA TRIBUNAL est une plateforme numérique de géolocalisation et d’information consacrée aux tribunaux pour enfants en République Démocratique du Congo.
La plateforme vise à aider les citoyens, familles, avocats, magistrats, greffiers, travailleurs sociaux, organisations de protection de l’enfant, chercheurs et institutions à identifier plus facilement une juridiction, consulter ses informations pratiques et obtenir un itinéraire.
3. Problème traité
Les informations relatives aux tribunaux pour enfants sont souvent dispersées, difficiles à vérifier ou insuffisamment accessibles en ligne.
Un utilisateur peut rencontrer des difficultés pour :
    • connaître le nom officiel d’un tribunal ;
    • trouver son adresse exacte ;
    • déterminer la province, la ville ou le territoire concerné ;
    • obtenir ses coordonnées géographiques ;
    • vérifier ses contacts institutionnels ;
    • connaître son ressort territorial ;
    • trouver un itinéraire fiable depuis un smartphone ;
    • distinguer une donnée vérifiée d’une information provisoire.
LUKA TRIBUNAL vise à réduire ces difficultés par la constitution progressive d’un référentiel national géolocalisé.
4. Vision
Créer une plateforme nationale de référence, neutre, accessible et sécurisée permettant une meilleure orientation vers les juridictions spécialisées dans la protection de l’enfant en République Démocratique du Congo.
5. Proposition de valeur
LUKA TRIBUNAL permettra à un utilisateur de :
    1. rechercher un tribunal pour enfants ;
    2. le visualiser sur une carte ;
    3. consulter sa fiche institutionnelle ;
    4. connaître le statut de vérification des informations ;
    5. obtenir un itinéraire ;
    6. signaler une erreur éventuelle.
L’expérience principale doit pouvoir être réalisée rapidement depuis un smartphone, y compris avec une connexion limitée.
6. Publics visés
La plateforme s’adresse notamment aux :
    • citoyens ;
    • parents et familles ;
    • avocats ;
    • magistrats ;
    • greffiers ;
    • assistants sociaux ;
    • policiers spécialisés dans la protection de l’enfant ;
    • organisations non gouvernementales ;
    • organisations internationales ;
    • chercheurs ;
    • étudiants en droit ;
    • institutions judiciaires ;
    • partenaires techniques et financiers.
7. Objectif général
Concevoir et déployer une plateforme web responsive permettant de localiser les tribunaux pour enfants en RDC et d’accéder à leurs informations institutionnelles et géographiques utiles.
8. Objectifs spécifiques
Le produit devra progressivement permettre de :
    • localiser les tribunaux sur une carte interactive ;
    • utiliser la position de l’utilisateur avec son consentement ;
    • rechercher une juridiction par nom ;
    • rechercher par province, ville ou territoire ;
    • filtrer les résultats ;
    • afficher l’adresse et les coordonnées ;
    • fournir un itinéraire ;
    • afficher les contacts institutionnels disponibles ;
    • afficher le ressort territorial ;
    • indiquer la source et la date de vérification ;
    • signaler une information incorrecte ;
    • administrer et valider les données ;
    • conserver un historique des modifications ;
    • constituer progressivement une base nationale fiable.
9. Principes du produit
9.1 Simplicité
L’utilisateur doit pouvoir atteindre la fiche d’une juridiction en trois actions principales maximum.
9.2 Accessibilité
La plateforme doit être utilisable sur smartphone, tablette et ordinateur.
Elle doit tenir compte :
    • des connexions lentes ;
    • des écrans de petite taille ;
    • des utilisateurs peu familiers avec les outils numériques ;
    • des besoins futurs de traduction dans les langues nationales.
9.3 Fiabilité
Chaque information doit, dans la mesure du possible, comporter :
    • une source ;
    • une date de collecte ;
    • une date de vérification ;
    • un statut de validation ;
    • un historique des modifications.
9.4 Neutralité
La plateforme ne doit :
    • soutenir aucun parti politique ;
    • afficher aucune publicité politique ;
    • privilégier aucune province sans justification fonctionnelle ;
    • publier aucune opinion sur les décisions judiciaires ;
    • être utilisée comme outil de propagande.
9.5 Protection de l’enfant
Le système ne doit contenir ni publier :
    • le nom d’un enfant ;
    • l’identité d’une victime mineure ;
    • l’identité d’un enfant en conflit avec la loi ;
    • le contenu d’une plainte ;
    • un dossier judiciaire individuel ;
    • les détails d’une affaire en cours ;
    • une décision confidentielle ;
    • une donnée personnelle inutile à la géolocalisation.
9.6 Sécurité
La sécurité doit être intégrée dès la conception.
Les données, les comptes administratifs, les secrets techniques et l’historique des modifications doivent être protégés.
10. MVP expérimental
Le MVP du premier mois devra inclure :
    • une page d’accueil ;
    • une carte interactive ;
    • la recherche par nom ;
    • la recherche par province et ville ;
    • la géolocalisation avec consentement ;
    • l’affichage des tribunaux pilotes ;
    • une fiche par tribunal ;
    • l’ouverture d’un itinéraire ;
    • l’affichage des contacts disponibles ;
    • un formulaire de signalement ;
    • une administration minimale ;
    • une version publique accessible à environ dix testeurs.
11. Éléments exclus du premier MVP
Ne font pas partie du premier MVP :
    • dossiers judiciaires ;
    • plaintes nominatives ;
    • intelligence artificielle juridique ;
    • chatbot donnant des conseils juridiques personnalisés ;
    • statistiques judiciaires sensibles ;
    • application mobile native ;
    • mode hors connexion complet ;
    • notifications push ;
    • paiement ;
    • publication automatique de données non vérifiées ;
    • API publique ouverte.
12. Mesures de réussite
Le MVP sera considéré comme réussi lorsque :
    • il sera accessible en ligne ;
    • dix personnes pourront le tester ;
    • les juridictions pilotes seront affichées correctement ;
    • la recherche fonctionnera sur smartphone ;
    • la géolocalisation pourra être autorisée ou refusée sans bloquer le service ;
    • un itinéraire pourra être ouvert ;
    • les données sensibles seront absentes ;
    • les utilisateurs pourront signaler une erreur ;
    • les retours permettront de définir la version suivante.
13. Vision à trois mois
Mois 1
MVP expérimental et test utilisateur.
Mois 2
Administration, validation, historique, sécurité renforcée et corrections.
Mois 3
Stabilisation, tests, documentation, sauvegardes, monitoring et préparation institutionnelle.
14. Vision à long terme
L’architecture pourra évoluer pour intégrer :
    • les parquets ;
    • les cours d’appel ;
    • les tribunaux de paix ;
    • les tribunaux de grande instance ;
    • les services d’aide juridique ;
    • les services sociaux ;
    • une application Android et iOS ;
    • une API pour partenaires autorisés ;
    • un mode hors connexion ;
    • un tableau de bord national.
Toute extension devra respecter les principes de neutralité, de protection de l’enfant, de minimisation des données et de validation institutionnelle.
